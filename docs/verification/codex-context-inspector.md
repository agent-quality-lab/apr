# Codex local context inspector: acceptance record

Tested on macOS with Codex CLI 0.166.0, the APR stdio bridge, loopback workspace and disposable SQLite stores. This is CLI acceptance, not global installation or desktop hook support. See the [operator walkthrough](../operators/codex-context-inspector.md) for the capture commands and limits.

| Check | Evidence |
| --- | --- |
| Real task, two turns | An isolated authenticated Codex session drafted an operator handoff from the public APR guide, then resumed under its explicit session ID and checked the final handoff against the public recording skill. Both calls reported the same native session. An APR-disabled control independently read the same guide and identified the required human inputs. |
| Task, context and delivery | The operator used the MCP to start a single task with the exact run brief and two criteria before substantive work. Three selected files had inventory receipts. Turn 1 matched the guide; turn 2 matched the skill; the third file had no observed read. The recorded final result matched the second-turn delivery. |
| Provenance and gaps | Turn 1 attempted an MCP append that required interactive approval in noninteractive Codex. The operator preserved the returned draft as an agent report, disclosed the missed in-turn write and recorded the final delivery through the MCP. The observer flagged the unsupported tool. This does not establish unattended agent-driven lifecycle writes. |
| Workspace and human handoff | The real loopback inspector displayed the brief, result, both per-turn reads, unobserved inventory item, gap, agent report and pending review link. Restarting only the disposable service preserved the link, both turns, agent reports and pending review. No rating was generated for the demonstration. Browser fixtures additionally covered a saved rating, later evidence, keyboard disclosure and mobile layout. |
| ASK compatibility | Two further isolated executions of the installed CLI used the same deterministic loopback Responses peer, with no real model or account credentials. Each read the four actual bootstrap files in order, followed by the project index, framework, software index, local integration status and runtime contract. The control had no APR MCP or collector; the enabled execution had per-process APR MCP and piped its command stream to the collector. All nine commands succeeded in the same order and all nine outputs matched byte lengths and SHA-256 in both runs. The collector matched every file and labeled an additional unrecognized event. This verifies the specified retrieval path, not equivalence of arbitrary model decisions. |
| Isolation | The two-turn task used only public APR material with the model provider; ASK compatibility was tested locally. The inspected ASK and global runtime files matched their pre-run fingerprints. No vault, installed skill, hook, global config, website, publication or real APR history was changed. |

The regression suite exercises opt-out before store access, secret and symlink rejection, bounded input, failed and partial commands, cross-session and exact-stream replay, transaction conflicts, human-only reviews, frozen evidence and share exclusion. The replay guard was added after the real two-turn capture; its regression checks and the later enabled ASK parity check used the final receipt format. Private records and transcripts are not repository fixtures.
