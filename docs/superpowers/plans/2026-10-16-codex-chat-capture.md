# APR first Codex chat-capture slice — CTO plan

Date: 2026-10-16  
Scope: execution-ready plan for the local integration repository at the APR checkout, starting from merged `main` at `64c2d13`. This records the accepted planning baseline. Implementation and verification are recorded separately in `docs/verification/codex-chat-capture.md`.

## Outcome and boundary

Build a local Codex adapter that automatically records content-free lifecycle evidence into one durable APR review per native Codex chat/session, across turns and process restarts. It creates a stable local review URL for that native chat and the review page reads its accumulated event projection. Capture is independent of opening the URL. This slice does not claim the assistant footer is automatic: current Codex hook documentation supports lifecycle hooks and warnings/context, but does not document mutating a completed assistant message into a clickable Markdown footer. The `Stop` continuation path starts another model request and is prohibited by the accepted runtime contract.

Scope is the local core migration/API, Codex command-hook adapter, event-derived review projection, synthetic/native-payload fixture coverage, setup/diagnostics documentation, and a disabled/example hook definition. Keep the current manual `request_rating` / `record_review` behavior and all existing jobs, URLs, snapshots, saved ratings, and import provenance readable and intact. Do not read/import legacy history. Do not implement website, account, cloud, sharing, other runtimes, or change installed Codex configuration. One PR for this first capture slice; any later supported footer/presentation mechanism is a distinct capability and PR.

## Evidence and runtime constraints

The official [Codex Hooks reference](https://learn.chatgpt.com/docs/hooks) currently documents common `session_id` and active `model`, turn-scoped `turn_id`, `SessionStart.source` values (`startup`, `resume`, `clear`, `compact`, `fork`), and local `PreToolUse` / `PostToolUse` fields including `tool_use_id`. It says subagent hooks share the parent `session_id`; local tool hooks cover shell, MCP, and many local tools but not hosted tools. `UserPromptSubmit` includes the prompt, and `PostToolUse` contains tool name, input, and possibly output: the adapter must discard these fields before any persistence or logging. The page says transcript files are not a stable hook interface. `Stop` with a blocking decision asks Codex for another continuation prompt; `systemMessage` is surfaced as a warning/context and does not establish a clickable footer. `SessionStart.additionalContext` is added to model context, so do not use it to smuggle a URL or silently add token overhead.

Installed CLI is `codex-cli 0.152.1`. `codex hooks --help` has no hooks subcommand; this was a read-only check. Documentation establishes the available payload shape, not actual per-chat ID continuity across resume/restart, exact current desktop behavior, complete hook coverage, or footer insertion. Resume identity is therefore an acceptance gate. A changed/missing native ID must create a new unlinked record with an explicit continuity gap; never join by recency, cwd, model, or a global “active chat.”

## Data model and migration

Add migration 3 only; never rewrite migrations 1 or 2. Keep the current `jobs` key and snapshot columns as the review/rating surface. Add:

- `runtime_bindings(runtime, installation_key, native_chat_key, identity_source, review_id UNIQUE REFERENCES jobs, first_seen_at, last_seen_at, start_source, adapter_version)`, with a unique key on `(runtime, installation_key, native_chat_key)`. `native_chat_key` is an HMAC of the runtime's native ID using a random per-store local salt, so raw Codex session IDs are not retained. The store itself is the installation namespace for this single-user local MVP. A local generated `review_id` (e.g. `apr-<uuid>`) is distinct from both the native ID and any caller-supplied ID.
- `runtime_events(event_key PRIMARY KEY, review_id REFERENCES jobs, turn_key, kind, observed_at_utc, observed_monotonic_ns, clock_epoch, model_slug, safe_tool_category, tool_key, source, adapter_version, schema_version)`. `tool_key` is a keyed hash of Codex `tool_use_id`; no raw event object or arbitrary JSON blob is stored. Index by `(review_id, turn_key, kind)`.
- `runtime_turns(review_id, turn_key, first_observed_at, terminal_observed_at, terminal_kind, first_model, last_model, coverage)` with primary key `(review_id, turn_key)`, updated transactionally from events. Use first-write-wins for first/terminal event timestamps and unique event keys so retries cannot extend or double-count a turn.

When first binding a chat, atomically create its `jobs` row with a generated `job_token` and an explicit sparse snapshot (`job_type: other`; task/action/result and unavailable fields `unknown`; runtime `codex`; verification `unknown`). Update `request_rating` input contract only if needed to accept this reserved generated ID; never overwrite an existing job when an identity collides. Keep generated chat IDs in a namespace distinguishable from existing IDs. The local review card renders “No task summary captured” for placeholders and shows event-derived measures from a read-only projection, not by rewriting the caller's snapshot. Existing `saved_snapshot` / `saved_full` remain frozen; later events remain visible as new run evidence with a clear “evidence after rating” timestamp, never silently changing the rating's scope.

Create store methods `ensure_runtime_job(identity)`, `ingest_runtime_event(identity, normalized_event)`, and `runtime_review_projection(review_id)`. Put strict normalization/allowlist validation in `review_schema.py`. Add a private internal service endpoint for the Codex hook or call the SQLite store directly from the adapter. Preferred first slice: direct `ReviewStore` transaction per hook invocation keeps capture independent of MCP calls/service lifetime and avoids network and service-start dependencies; verify SQLite/WAL concurrency with the existing bridge and store. It must use the same per-user data directory and existing private file/lock conventions. If direct writer isolation proves unsafe in synthetic concurrent tests, use a narrowly authenticated loopback endpoint as a design revision, still without returning output to Codex.

The projection joins `runtime_events` to the specific `review_id`: observed distinct turn count/order; per-turn elapsed when start/end are both observed; sum of complete observed turn spans; chat wall span from first to last observed event; tool count/category counts from distinct `tool_key`; model slugs per turn and observed model changes; terminal states; and coverage gaps. It must appear on the review page reached by this chat's stable URL, not in a separate orphan analytics table. Never update `jobs.snapshot.resources` with computed values that could be mistaken for caller-entered measurements.

## Codex identity and event semantics

Root chat identity is `(runtime='codex', installation namespace, HMAC(session_id))`. Require nonempty `session_id`; malformed payloads are ignored with only a sanitized diagnostic counter where a functioning store permits it. Two different native IDs always map to different generated review IDs and URLs, even when their events interleave. Same native ID on `resume`/restart resolves to the same binding and URL. `source='fork'` creates a new chat binding, never aliases the parent. `clear` is a new logical chat boundary unless runtime acceptance evidence proves the same thread is still the intended job; default is a new ID mapping and coverage notice. `compact` is same chat and contributes no turn count.

Ingest `SessionStart` for identity/source/model and coverage start; `UserPromptSubmit` as observed turn start using only `turn_id` (never `prompt`); `PreToolUse`/`PostToolUse` only to measure paired elapsed time and count supported local tool invocations; `Stop` as `turn_stopped`; and `Interrupt` as `turn_interrupted`. A `Stop` event means Codex stopped that turn; it does not mean the task succeeded. Do not use `SessionEnd` as turn completion. Hosted-tool gaps and a missing `PostToolUse` leave a tool interval/capture gap rather than a guessed duration. Subagent attribution is incomplete in this first slice: hooks reuse the parent session ID and tool payload documentation does not establish a child ID on every tool event. Record a bounded delegation-observed indicator only if the safe `SubagentStart/Stop` fields can be mapped; do not fold unidentified child calls into root totals and expose this gap in coverage.

Idempotency: derive turn event keys from `(native_chat_key, turn_id, kind)` and tool event keys from `(native_chat_key, turn_id, tool_use_id, phase)`, HMACed with the local salt. `tool_use_id` is documented for pre/post tool hooks. Use `INSERT ... ON CONFLICT DO NOTHING` for immutable observations and update turn projection in the same transaction only when a new event row was inserted. Session-level starts update binding metadata; they do not inflate event/turn counts. Retrying the same fixture or actual payload is safe. If a required native identity is absent, reject attribution rather than inventing a new ID for every hook.

## Timing, usage, and coverage

Codex hook payloads do not document event timestamps, token totals, or cost totals. Timestamp each event at local hook receipt. Store UTC for display and monotonic nanoseconds plus a host boot/clock epoch for interval math; if a valid epoch cannot be established or monotonic order is impossible, duration is unknown. Report “Codex turn elapsed” as local observed wall time between `UserPromptSubmit` and `Stop`/`Interrupt`; it includes model/tool/approval waiting and is not model compute time or human active time. Report chat wall span separately, including gaps between turns. Do not name either one generic “active time.” A turn missing start or terminal event has null duration and an open/incomplete status.

Resource values: tool occurrences and category are measured from supported observed local tool hooks; tool identities, arguments, results, path and document values are never stored. `tokens`, `cost`, roles, and loop count remain the string `unknown` unless a later verified runtime source supplies exact values and provenance. Never infer zero from absent events or estimate from model names. Model slug is captured only when explicitly supplied and can vary by turn.

Every projection shows `capture started at`, `first/last observed event`, start source, adapter/schema versions, observed turn count, open/incomplete turn count, and an honest coverage label. Use `partial`/`late_start` when capture begins on resume, a required event is missing, a tool path is unsupported, or the adapter reports failure. A clean `Stop` is not proof that all events were received; never label capture complete from hook success alone. Earlier turns before opt-in remain unmeasured and cannot be backfilled from transcript/history. Failed events should fail open for Codex (empty stdout, no blocking decisions) and write only a sanitized failure class to local diagnostics; tests must show the failure is visible as a coverage gap when persistence is available.

## Privacy allowlist

Persist only: fixed runtime name `codex`; local opaque review ID; HMACed native session, turn, and tool-call IDs; enumerated lifecycle kind; adapter/schema version; event-observed UTC/monotonic values and clock epoch; explicit model slug; start source enum; safe broad tool category enum; derived counts/durations; coverage/error class. The adapter may transiently parse input JSON but must read only the allowlisted fields and discard the rest. Never store or print prompt/assistant text, tool names, tool input/output, `cwd`, transcript/subagent transcript paths, arbitrary event JSON, permission mode, secrets, or raw native IDs. Do not inspect transcripts or legacy run history.

## Acceptance tests for the author

Use isolated temporary data directories and synthetic payloads only; no actual Codex config, transcript, ratings, or user DB.

1. Native payload fixture: parse official-shaped `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, and `Interrupt` payloads. Put unique bait prompt, command, output, cwd, and transcript paths in fixture; assert no bait appears in DB files, projections, exception text, stdout, or adapter logs. Assert model/source/turn IDs and safe category are retained only in allowed/hash form.
2. Interleaved chats A/B with different session IDs, alternating three turns and tools: each has a different review ID and URL; all A events aggregate only to A and all B only to B. Review link resolved from either arrival order yields its own chat projection.
3. Replay each event, including `PostToolUse` with the same `tool_use_id`, and retry after simulated commit/response ambiguity: event count, tool count, turn spans, model changes, and URL remain unchanged.
4. Dropped/missing event: omit `PostToolUse`, `Stop`, or an early `SessionStart`; the projection reports missing/late/open coverage, not zero duration, complete capture, or a synthetic prior turn. A hook store failure leaves Codex unblocked and records a safe diagnostic/coverage gap when storage returns.
5. Stop and interrupt: `Stop` closes only its observed turn as stopped; `Interrupt` marks interrupted and does not claim success. Neither emits stdout/context or starts another model request. Missing `Stop` remains open after process/service restart.
6. Resume/restart: same synthetic native `session_id` on startup then resume after closing/reopening SQLite returns the same review ID and URL, and new turns join it. A new session ID on resume creates a separate record marked continuity-unverified; no recency/cwd merge. `fork` creates a new review. This is a deterministic unit test, not proof Codex itself preserves its ID; before any full-support claim, a separately authorized isolated Codex acceptance run must confirm actual same-chat `session_id` continuity across resume and app/CLI restart.
7. Card projection: opening the per-chat URL shows cumulative event metrics on the review the user is rating. Repeated reads preserve URL. Saved rating contents remain frozen while later event evidence is explicitly dated and scoped.
8. Regression: all current manual review, save/skip, stable URL, restart, import-preservation and MCP bridge behavior remains unchanged under existing tests.
9. Trust boundary: PR contains only an example/opt-in collector definition. Verify no command changes installed `~/.codex` files and no hook is enabled during synthetic tests. The user must review/trust the exact hook definition under Codex's hook trust UI before a later activation; changed hashes require re-review.

## Rollout, rollback, and user trust

Merge only the local capture PR after these checks. Roll out to synthetic fixtures first, then a user-authorized isolated Codex runtime walkthrough. Keep hooks disabled by default in the actual Codex profile; do not add user-level registration, alter feature flags, or trust hooks as part of code delivery. Explicit activation is a separate operator action: inspect the exact command and paths, install/enable the documented hook definition, review/trust its hash in Codex, verify capture in two interleaved synthetic chats, then run a deliberately chosen harmless real multi-turn chat after consent. This trust step authorizes local event collection, not transcript reads or sharing.

For rollback, disable/remove only the collector hook definition and leave the local SQLite database and existing review records untouched. Schema migration is additive and old application code ignores the new tables; no destructive rollback or rating rewrite is needed. Keep events private; no network upload or website writes.

## Remaining blocker

The capture/data slice is implementable now. Full accepted Codex UX is blocked on demonstrated native clickable footer insertion and a native chat-ID handoff to that rendered link. The published hook reference documents no append-footer API. Do not have the assistant call MCP or put the link in `additionalContext`/`systemMessage` and claim zero-token automatic footer support. Until a supported surface is established, expose the stable chat review URL through APR's local captured-chat listing/projection and label assistant-message footer association as a remaining limitation. Also gate any claim of cross-resume continuity on the isolated runtime identity test described above.
